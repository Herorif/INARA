# Supported route/policy matrix (R7)

The [machine-readable inventory](ROUTE_POLICY_MATRIX.json) covers **111 desktop socket routes, `/status`, 47 dispatcher tools (33 model-visible) and ten isolated HTTPS mobile routes** and the two Live voice function declarations (`ask_brain`, `end_conversation`). Live voice reaches tools only through `ask_brain`, a normal brain turn on the common conversation tool catalog; reviewed push-to-talk dictation is unchanged. The old always-on voice routes (`start_audio`, `resume_audio`, `pause_audio`, `stop_audio`, `upload_memory`, `video_frame`) and the frame-less camera tools (`describe_camera`, `detect_presence`, `watch_for`, `list_watches`, `stop_watching`) were removed; see [RETIRED_PATHS](RETIRED_PATHS.md). `start_audio` remains only as the permission key shared by push-to-talk `speech_capture`.

## Policy conventions

Validated `False` / `allow_within_scope` permits an action, `deny` rejects, and `True` or missing policy requests owner approval. Aliases preserve canonical, source and target denials. Live voice hands tool work to the brain, whose dispatcher calls keep their approvals, with the voice session's authorization checked before and after each approval. Owner safety controls remain independent of editable permissions.

The autonomous browser compatibility names are retired. `browser_inspect` is desktop-only and not advertised to the model; `browser_cancel` also cancels pending approvals. [Read-only browser policy and acceptance](BROWSER_INSPECTOR.md).

## Remaining sequence

## R6 quick assistant and reviewed speech

Five `speech_*` routes use generated SpeechBegin/Frame/Turn/Send contracts. They authorize the pinned owner renderer and capture project/conversation/turn/SID scope. Preparation uses the hidden `speech_capture` tool and existing `start_audio` permission. Capture is explicit, one turn at a time, with mono 16 kHz PCM16, 20 ms/640-byte frames, exact sequence/timestamps, a 20-second cap, eight queued renderer frames and bounded transcription. Only reviewed Send calls the common conversation/dispatcher. `cancel_conversation` cancels typed work for the origin SID. Cancellation, device loss, disconnect, project/lock/resource changes, panel closure and core shutdown invalidate work without replay. See [R6 evidence and limits](R6_QUICK_ASSISTANT.md).

## R7 isolated phone access

The six `mobile_*` socket controls require the unlocked pinned desktop owner/renderer. They inspect or explicitly enable/stop the dedicated TLS listener, create/cancel expiring invitations, approve a fingerprint and revoke a device. No mobile action is added to the model tool catalog. The separate HTTPS API has strict claim/finish/status/jobs/preview/chat/history/receipt contracts, bound public-key authentication, durable replay rejection and narrow owner/device/project grants. It is not mounted on the desktop API. Phone chat uses an empty dispatcher and cannot import desktop transcript history. [Full protocol and pending Android acceptance](R7_ANDROID_FOUNDATION.md).
