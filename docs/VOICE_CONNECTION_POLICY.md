# Shared voice dispatch and connection/face ownership (R2b5)

> Renamed from INARA on 5 Nov 2026; data and settings migrate automatically.

Implemented 19 October 2026. This completes the two authorized follow-up steps from [Workspace policy](WORKSPACE_POLICY.md): shared voice execution and connection/face-task ownership.

## One active tool authority

Superseded: live voice now declares only `ask_brain` and `end_conversation`; `ask_brain` runs a normal brain turn whose tool calls go through `ToolDispatcher` (see ROUTE_POLICY_MATRIX). Historical: `VoiceBridge` generated the live catalog from dispatcher argument models and sent every function call through `ToolDispatcher`. The old `AudioLoop.receive_audio` tool switch no longer executes. The old inventory recorded only 26 declarations in `tools.py`; the live config had additional declarations in `inara.py`. The replacement explicitly maps **37 active voice names** to shared targets, including the retained prototype alias. The original static metadata remains unused by the active catalog pending R2c deletion.

The root now registers 53 tools, 40 provider-visible for text. Strict shared contracts were added for project selection, directory listing/search, routines, desktop/window/clipboard actions, camera/watch actions, device state and configured-printer status. Existing file, reminder, local action, printer pipeline and workspace services remain the authorities. Compatibility aliases retain canonical and target denials. Voice CAD prompts use the same retained legacy workflow as the old direct panel, rather than replacing the typed parametric-build schema. Project search/listing stays inside the captured project and is bounded; it no longer implies arbitrary home-directory traversal.

Voice calls validate arguments, use the same owner-bound approval/expiry/denial path and recheck their trusted session before and after waiting. Stopping voice cancels its pending approval/execution tasks even if sibling/native channels remain. Unsupported functions return a structured unavailable result. Implicit Google Search is omitted; browser work remains an explicitly approved shared action. UUID/binary review values are serialized safely for sockets while execution retains typed validated objects.

Each call captures owner, origin and project. A bound project-manager view keeps voice history and file tools independent of unrelated global project changes. An authorized voice project switch updates the binding for subsequent calls. Delayed bus events capture a trusted session guard and are discarded after that generation stops. Voice results reflect awaited work rather than claiming success when detached work merely starts.

Live SDK declarations are validated locally through the installed Google SDK. The optional audio constructor no longer creates CAD/browser/Kasa/printer agents. Its SDK client and audio engine belong to the session instance; the stop path closes its streams/client/engine. Physical microphone/speaker behavior and driver-blocking calls remain unverified. The unchanged audio transport still needs R6 acceptance and potential worker isolation.

## Owner-only connection state

`ConnectionTransport` owns connect/disconnect, initial hydration and the optional face generation. Token/UUID validation remains in `DesktopSessions`. Foreign principals are rejected at the connection boundary after the desktop owner is pinned. The native control channel may register the first owner before renderer startup.

Control/resident channels receive no project/settings/printer/watch/reminder hydration. Locked owner renderers receive only connection/resource/authentication metadata and scoped face frames. Successful authentication hydrates verified owner renderer rooms. There are no global authentication broadcasts. Last-renderer disconnect, settings changes, gaming/resident restrictions and shutdown invalidate the generation before cleanup; stale worker frames/status cannot unlock a later generation. Reopening a face-enabled workspace requires authentication again.

Concurrent renderer connects share one face task. A failed/completed generation is retained until explicit settings/reconnect lifecycle changes, avoiding silent repeated camera acquisition. Setup validation rejects enabling face verification before persistence when the installed model or reference image is missing. It does not download models automatically. Reference lookup prefers `backend/reference.jpg`, then `<workspace_root>/reference.jpg`; the installed model is `backend/face_landmarker.task`. No model/reference/hardware was configured in this batch.

## Owned face process

The optional `FaceWorker` uses the existing Windows kill-on-close Job Object, a fixed worker entry point and a pipe-only bootstrap. Heavy OpenCV/MediaPipe imports and blocking camera work stay in that child. The worker accepts only a trusted reference/output path, emits bounded local status/frame reports and has a 120-second deadline. Process close stops the owned tree, then removes transient frame/status files. Bounded cleanup accommodates Windows retaining a stopped process's working-directory handle briefly.

The worker adapter uses the Windows camera backend rather than the prior macOS-only backend constant. This is an implementation correction, not a physical-camera acceptance result. Face landmarks remain a convenience gate and are not OS-grade identity verification. A corrupted/missing face setup fails closed with a scoped error. Model inference and matching accuracy are unverified.

## Tray voice: the local endpoint (J2)

Added 5 November 2026. A live voice session now has one of two endpoints. `renderer` is unchanged: the owner's renderer captures the microphone (AudioWorklet), plays JARVIS's speech and is the only room that receives `voice_state`, `voice_caption`, `voice_audio_out` and `voice_interrupted`. `local` is new: the resident core itself captures this PC's microphone and plays through its speaker, so the owner can talk to JARVIS from the tray with the workspace closed. The talking overlay (J4) that shows a tray session is described below. The "Hey Jarvis" wake word is described below and in [WAKE_WORD.md](WAKE_WORD.md); with it off, the microphone is open only during a tray session started with **Talk to JARVIS**.

**Who and when.** The tray's Talk to JARVIS (Stop talking while a session runs) starts a session for the registered local owner. There is no renderer SID; the equivalent authorization is the registered owner, an unlocked face gate, and the shared `start_audio` / `speech_capture` permissions not set to deny, rechecked at start, after the devices open, each second and around every brain approval, exactly as for the renderer. Tray voice is allowed in the `resident` resource state (that is its purpose) and in `chat`/`studio`; gaming mode refuses it and stops a running session at once (the resident restriction leaves it running). Usage tickets and budget caps are unchanged (`voice_live` per Live turn, `voice_brain` for hand-offs). There is still one live session per owner across both endpoints: starting one while the other runs returns `voice_busy` ("Voice is already on from the tray. Stop it there first." / "Voice is already on in the workspace. Stop it there first."). Renderer stop and disconnect never reach a tray session.

**Mode and lifetime.** Always hands-free `conversation` with Gemini server VAD. It ends on the existing 60-second silence watchdog, `end_conversation`, Stop talking, gaming mode, lock, project change, a lost device and quit. The tray tooltip shows Connecting / Listening / Thinking / Working / Speaking with the microphone state (on, paused while JARVIS speaks), plus a notice: a saved device that is not connected ("using the system default"), a lost device, or why a start was refused.

**Audio path.** `services/audio_devices.py` imports `sounddevice` (PortAudio, raw int16, no NumPy) lazily on one dedicated audio control thread, which runs every PortAudio control call (initialize, query, open, start, abort, close). Devices come from the Windows WASAPI host API, identified by name and host API, never by index. WASAPI shared mode runs at the device's mix rate, so the microphone records at the device rate (20 ms blocks) and is resampled to 16 kHz 40 ms frames for Live; Live's 24 kHz speech is resampled to the speaker's rate (`telephony.audio.Resampler`, a polyphase Kaiser filter; speech quality). A device that only opens with its own channel count is down- or up-mixed. PortAudio callbacks never block and never call into the core: they copy one block into a bounded deque (1 s of microphone, 2 min of speech; the oldest block is dropped on overflow and counted) and wake the core loop with `call_soon_threadsafe`. A saved device that is missing falls back to the system default and says so. A device that stops (PortAudio finishes the stream, or no callback for 2 s) ends the session with "The microphone (speaker) was disconnected. Voice is off." and both streams are released.

**Half-duplex echo control (v1).** While JARVIS's audio is playing, and for 300 ms (plus the reported output latency) after the playback buffer drains, microphone frames are dropped instead of being sent to Live, so JARVIS does not hear itself. `voice_interrupted` flushes the playback buffer at once, including a part-played block, and keeps the tail. Because Live cannot hear the owner while JARVIS speaks, saying "Hey Jarvis" is the voice barge-in (below); Stop talking also interrupts. Acoustic echo cancellation is out of scope.

**"Hey Jarvis" (wake word).** `services/wake_listening.py` runs the local detector (`services/wake_word.py`) in the native resident only, never in a bare server or test app, in the resident, chat and studio states. Setting `voice.wake_word` (default on) and `voice.wake_sensitivity` (low / normal / high, default normal) are saved through `update_settings` or the tray's **Listen for "Hey Jarvis"** (checked while on), which saves the same setting and emits `settings` to the owner's renderers. The microphone is held only while the setting is on, the detector's extras and models are available, the owner is registered, `voice.ready()` passes, `start_audio` / `speech_capture` are not denied, gaming mode is off, and a microphone exists; this is checked again on `voice` / `tool_permissions` changes, resource-state changes, owner registration, the end of a tray session and every 30 s while not listening. Gaming pauses it (the models stay loaded); turning it off stops the detector and drops its models. There is never more than one capture stream: while listening, `audio_devices.Microphone` is opened once at 16 kHz mono through WASAPI's own conversion (`WasapiSettings(auto_convert=True)`, 20 ms blocks; blocks go from the PortAudio callback to the detector's non-blocking queue) or, if refused, at the device rate with resampling on a capture worker thread; tray sessions attach to that stream and leave it open when they end, and nothing reaches the core loop per block until one does. With the setting off, tray voice opens and closes its own microphone exactly as before. A lost microphone ends a running tray session as above and is retried after 10 s, 30 s, then every 60 s, re-resolving the saved device each time. `audio_devices` briefly releases the stream so PortAudio can re-read devices, unless a session is running. A detection is decided on the core loop: no session, the wake cue then `start_local(wake=True)`, which sends the last 1.5 s of audio (kept in memory only) before the live frames and outside the queued-audio limit; a renderer session, ignored; a tray session while JARVIS is audible, barge-in (playback flushed, the tail ended at once, the rest of a still-streaming answer dropped until `interrupted`, `turn_complete` or 5 s, state back to listening, no cue, no pre-roll); a tray session otherwise, ignored. A refused start plays the denied cue and shows the refusal on the tray; face lock (`authentication_required`) also shows the fixed "Unlock JARVIS in the workspace to talk." notification at most once per 10 minutes. `wake_word_status` (owner renderer only, never opens a device) reports `off`, `listening`, `paused` (gaming only) or `unavailable` with a plain message, and the capability snapshot has a `wake_word` card. Details: [WAKE_WORD.md](WAKE_WORD.md).

**Conversation.** Tray turns are recorded in the conversation the workspace shows for the current project: the one it last restored (`resume_conversation` records it per owner and project, encrypted in the profile database), else the project's most recent conversation, else a new one. When tray voice had to choose or create one, the next `conversation_restored` carries `latest_conversation_id` and the workspace switches to it, so opening the window shows the spoken turns. An open workspace on that conversation is refreshed (`conversation_restored`) after each recorded turn, unless a typed turn is in flight. Captions, state and audio of a tray session never go to a renderer or workspace socket; only the owner's overlay sockets receive the overlay snapshot and output level (below). `ask_brain` runs unchanged; approvals go to the owner's open renderers, and with no workspace open the tool call returns `approval_unavailable` ("This needs your approval on screen. Open the JARVIS workspace, then ask again.") to the brain, which says so. Project memory is attached only for renderer-originated turns, so tray brain turns run without it.

**Privacy.** Audio is never logged or stored, by either endpoint. Logs carry device names, host APIs, sample rates and counters (blocks, drops, status flags, muted frames) only. The core's microphone is open only during a tray session, or while "Hey Jarvis" listens (audio stays on this PC until a detection; the 1.5 s pre-roll lives in memory only); the device list (`audio_devices`, owner renderer only) enumerates without opening any device.

**Setup state.** `sounddevice==0.5.6` is a core dependency. If it is missing or PortAudio cannot load, `audio_devices` reports `available: false` with a plain message, Talk to JARVIS shows the message on the tray, and the capability snapshot has a `voice_local` card (installed / configured / blocked only in gaming mode). The import is never made at core startup (tests/test_application.py).

**Verification.** `tests/test_local_voice.py` drives a fake PortAudio module and a fake Live session: resampling accuracy at 44.1/48 kHz, capture to 16 kHz frames, overflow drops, half-duplex gating and tail, interruption flush, stereo-only devices, saved/missing/absent devices, failed opens, device loss (finished stream and stalled callbacks), resident/gaming policy, lock and permission, one session per owner across endpoints, conversation targeting and adoption, approvals with and without a workspace, the silence watchdog and the resident tray action path. A smoke check enumerates this PC's real devices without opening one. `tests/test_wake_listening.py` covers "Hey Jarvis" the same way (fake PortAudio, a fake detector, a fake Live session): each listening condition, gaming pause, owner registration, lost-microphone backoff, the one shared capture stream, the 16 kHz open and its fallback, pre-roll exactness, the four detection cases and face lock, barge-in and its drop window, cues, the tray switch and tooltip, `wake_word_status` and the capability card. No real stream was opened: physical microphone/speaker behavior, WASAPI driver quirks, real echo levels and Live audio acceptance remain unverified.

## The talking overlay (J4)

Added 6 November 2026. While a tray voice session runs, the native host runs a small always-on-top window (a separate Electron process, `electron/overlay-main.cjs`; the window itself is described in [VOICE_OVERLAY.md](VOICE_OVERLAY.md)) that shows the live core and captions, then closes itself. Setting `voice.overlay` ("Show JARVIS while you talk", a strict bool, default on; a missing or non-bool saved value reads as on, `audio_contracts.overlay_settings`) is saved through `update_settings`.

**The `overlay` socket role.** `DesktopSessions.accept` maps `role: "overlay"` to its own role; any other unknown role is still a renderer. An overlay socket is accepted only for the registered owner (the native owner, or the pinned local owner): it never registers or pins an owner. On connect it gets the current `voice_overlay` snapshot, to that SID only, and nothing else: no `status`, no `text_ready` / `resource_state` / `auth_status`, no hydration, no face work. It is never in `ConnectionTransport.renderers()`, `DesktopSessions.context()` refuses it (so no handler can act with the owner's project context through it), every renderer, workspace and resident handler rejects it through its role set, and the owner-wide broadcasts that are not role-filtered (`resource_state` after a resource change, `resident_state` from the native host, reminder delivery) skip it. A rejected request may still get that handler's own refusal (an `error` with `authentication_required`, or the handler's idle/error status), never data (tests/test_voice_overlay.py sweeps every registered handler).

**Events from the overlay.** `overlay_stop` and `overlay_open`, owner-only through `require_owner(sid, {"overlay"}, allow_locked=True)`, payload `null` or `{}` only (`OverlayRequest`). `overlay_stop` is the tray's **Stop talking** (`VoiceService.stop_local()`, a quiet end). `overlay_open` is the tray's **Open JARVIS** (`NativeHost.open_workspace(quick=False)`, posted to the tray thread); without a native host it answers `workspace_unavailable`. ACKs are `{ok: true}` or `{ok: false, code, message}`.

**Events to the overlay** (the owner's overlay SIDs only; nothing is sent while none is connected). `voice_overlay` is a full snapshot `{session, state, user, user_final, jarvis, jarvis_final, approval, end}`, sent on connect and on every change, coalesced to at most 20 per second with the latest state winning; the end snapshot is never dropped and goes out at once. `state` follows the tray's mapping (`connecting`, `listening` (also for idle), `thinking`, `working`, `speaking` while audible), then `ended` (an `error` end too); before any session it is `ended` with `session: null` and `end: null`. An exchange starts when the owner's input transcription begins after the previous turn completed (`user` = the new words, `jarvis` = "", `approval` = false); output transcription updates `jarvis`; a completed turn marks both final; a barge-in (Live's `interrupted`, or "Hey Jarvis" while JARVIS speaks) marks `jarvis` final and keeps its text (the dropped rest of an interrupted answer is never shown). Texts are the ones the core already accumulates, trimmed, the last 300 (`user`) and 600 (`jarvis`) characters; what the conversation records is unchanged. `approval` is true once `ask_brain` hit `approval_unavailable` in this exchange (the overlay then offers Open JARVIS). `end` is `{kind, message}`: `quiet` for stopped / conversation_ended / silence_timeout; `now` for gaming_mode, authentication_required (face lock) and permission_denied, with `user` and `jarvis` cleared in that final snapshot and the overlay process closed at once; `error` for every other end, with its message. A start refused by `check_local_start` never produces a snapshot. `voice_level` is `{level}` in 0..1, sent only while the state is `speaking` and an overlay is connected (at most 20 per second), then one final `{level: 0.0}`; it is `min(1, 4 * rms / 32768)` over every 4th int16 sample the speaker actually played, the scale of the workspace player (`playback.worklet.js`), measured in the speaker callback only while an overlay is connected during the session (`LocalAudio.measure_level`, no NumPy). Caption text and the token are never logged. Details of the process lifecycle: [NATIVE_RESIDENT.md](NATIVE_RESIDENT.md#the-talking-overlay-j4).
