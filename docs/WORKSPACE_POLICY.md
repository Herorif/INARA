# Workspace compatibility policy checkpoint (R2b4)

Implemented 19 October 2026. This batch follows [device/print policy](DEVICE_PRINT_POLICY.md). It migrates retained memory, media, legacy CAD and browser entry points without configuring providers or enabling hardware.

## Ownership and contracts

The injected application constructs `WorkspaceService` and `WorkspaceTransport`. Ten existing wire names remain: save/upload memory, start/stop/pause/resume audio, video frame, generate/iterate CAD and browser prompt. The facade keeps aliases, removing about 500 lines of direct global handlers. Optional voice/CAD/browser libraries load only inside an authorized request.

Each request requires the authenticated desktop owner renderer. Models cannot claim identity/project through payload fields. Strict bounded schemas reject extra fields, coercible booleans/device indices, oversized transcripts/prompts/frames and ambiguous Windows filenames. The shared dispatcher enforces denial/approval and rechecks authority before execution. `legacy_generate_cad` has the `generate_cad` permission while preserving the public typed build tool's separate schema. Iteration also honors its own deny; browser prompts use `run_web_agent`; resume uses the start-audio permission. Stop/pause use independent owner safety authority, permitted while the face gate is locked, rather than an editable action permission.

`save_memory` writes an exclusive UTF-8 transcript under the captured project's `long_term_memory` directory. Existing files are preserved; historical root-level memories remain untouched. These are explicit plain-text project exports, not encrypted database records. Transcript size is bounded to 200,000 characters and 200 messages. Uploads are bounded user context for the active voice session in the same captured project. Private memory/frame approval dialogs show size/hash metadata instead of duplicating full bodies. Existing UI memory upload payloads remain valid.

Voice lifetime is bound to its origin SID, owner and project. Disconnect of the originating renderer stops voice even if another same-owner/native channel remains. A new start cannot replace a live session implicitly. Audio, transcription, CAD/browser callbacks and status updates target authenticated same-owner renderers; callbacks from a stopped generation are discarded. Detached voice adapter work is tracked and cancelled on stop. Root shutdown and resource restrictions own the requests/session/frame-monitor cleanup, including the latest frame and optional vision client. Resume, memory upload and frame forwarding require the current project voice binding. Encoded JPEG/PNG frames are bounded to 1 MB with signature checks and a two-per-second ingress limit; this is not an image-decoder or physical-camera acceptance test. The legacy adapters retain their existing image MIME assumptions. Per-frame permission prompts can be avoided only by explicitly enabling the validated frame action within scope; no camera grant is inferred from starting voice.

## Creative/browser compatibility

Direct legacy CAD requests retain the existing optional adapter, use the captured project's `cad/legacy` folder and serialize with the shared creative slot. Returned artifact paths must resolve within that folder and stay below 16 MiB; emitted STL bytes are read from the checked file rather than trusting an adapter's inline payload. Supported typed CAD jobs remain unchanged. The compatibility route does not promise arbitrary model-generated geometry is valid.

Browser work now owns a per-request adapter and closes its browser/provider resources on success, error and cooperative cancellation. Typed browser calls receive the trusted origin SID from the conversation transport. Origin disconnect cancels both pending conversation approvals and executing tools, closes the provider and invalidates old requests, even when a native/sibling channel remains. Root shutdown also cancels active turns. Cancellation does not replay a durable conversation request; compatibility browser/CAD requests themselves do not gain a durable effect ledger or transactional rollback.

Deadlines are 10 seconds for memory export/frames/resume, 30 seconds for voice setup/memory upload, 180 seconds for browser tasks and 300 seconds for legacy CAD. Approval time is separate. These are cooperative Python deadlines: executor work or subprocesses inside retained adapters can outlive cancellation. Hard process-tree ownership for legacy CAD/browser/audio remains worker-isolation work; autonomous browser effects and generated CAD code are not sandboxed by this envelope. No actual provider, browser website or generated script was invoked during QA.

## Voice approvals and event delivery

Public legacy approval IDs map to the current voice generation and owner, expire after 60 seconds and are removed on stop. A strict authenticated renderer confirmation cannot resolve an old or foreign session. The retained voice gate now honors `deny`, supports within-scope permission values, times out, fails closed without a callback and rechecks disablement after approval. This is a bounded bridge: the AudioLoop dispatcher still has its own tool execution and ad-hoc arguments; strict shared-tool schema/dispatch parity is not complete.

Voice/background events inherit trusted owner context. Unstamped events remain on the internal bus and no longer broadcast to clients. Face status/frame callbacks now target owner renderers. Full connection hydration and face-task lifecycle consolidation remain a separate seam; this change does not upgrade face landmarks into OS authentication.

## Verification

New tests inject fake audio/CAD/browser adapters and fixture bytes; they never acquire a microphone/camera, navigate a website or call a provider. Coverage includes every new route's owner/role/policy and malformed-input behavior, project export/no-overwrite, redacted approvals, stale/cancelled voice generations, locked/resource behavior, browser cleanup, typed origin cancellation, late callbacks and CAD artifact containment. The Google SDK converts all provider-visible schemas locally without requests. Old broadcast/global-state smoke cases were replaced with these scoped service tests.

The first full run passed 458 Python checks. Review then added typed-origin and sibling/stale-session cases. A later run exposed a native test fixture reading its report between file creation and completion; the fixture now publishes the closed report atomically. The final combined regression passes **462 Python checks**, with one Blender-dependent skip and one existing FastAPI/httpx deprecation warning. Scoped Ruff and Python compilation checks pass.

[Native evidence](qa/r2b4-native-verification.json) passed fresh-owner registration, real socket denial checks for the new workspace events, settings persistence, lazy denied imports, close/reopen/crash, reminder receipt, gaming and graceful stop. Short idle was 67.12 MB mean working set over 10 seconds with zero Electron processes; this is not a game benchmark. [Fallback evidence](qa/r2b4-fallback-verification.json) covers close/reopen/reminder/gaming/quit. [CAD desktop evidence](qa/r2b4-cad-verification.json) verifies actual box/bracket/enclosure exports and scene operations, Three.js GLB import, responsive widths, missing-key planner behavior and four worker exits; warmed resident recovery was about 66 MB. Build, all 26 frontend tests and scoped Ruff passed; no new visual-design work is claimed.

## Next implementation

R2b5 should finish the retained voice tool boundary: map each voice declaration to a validated shared action or an explicit unsupported capability, preserve necessary adapters, and verify direct/typed/voice policy parity and cancellation. Inspect connection hydration, owner-only state delivery and face callback/task lifetime at the same boundary. Keep generated-code/browser hard isolation explicit rather than treating an async timeout as process termination. Then R2c can remove obsolete declarations, facade references and duplicate lifecycle code before R3 UI/TypeScript/shared RPC consolidation.

Provider/model configuration, physical media/device/printer acceptance, real diffusion/Blender execution and the real-game benchmark remain deferred/unverified. WhatsApp reply drafting/sending remains excluded until specifically requested.
